# Dental ICD-10 DX-2 — per-tooth diagnosis picker + overrides Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the clinician curate a tooth's coded diagnoses — suppress a chart-derived one and add a tooth-level one the chart does not represent — shaping only the coded diagnosis layer (FHIR export + coded summary/tooltip), never the visual chart.

**Architecture:** A per-tooth `dxOverrides: Map<DiagnosisKey,"add"|"suppress">` on `ToothState` (additive, payload 2.21) is applied inside `deriveDentalDiagnoses` (effective = derived − suppressed + added), so the FHIR export and every summary/tooltip consumer reflect overrides with no new coupling. A new "Diagnoses" card (composable-card pattern) reads a `getActiveDiagnoses()` view-model and writes via `setDxOverrideForSelection` through the DS-1 gate.

**Tech Stack:** TypeScript, Vite library, Vitest (jsdom), React 18; the `src/dx/` + `src/surfaces/` + `src/odontogram.ts` layers.

```ts
import { DX_CODES, type DiagnosisKey } from "./codes";
const ALL_DX_KEYS = new Set(Object.keys(DX_CODES) as DiagnosisKey[]);

export type DxOverrideMode = "add" | "suppress";

/** Apply a tooth's dxOverrides to its derived key set: `suppress` removes a key,
 *  `add` includes a valid tooth-level key. Unknown keys / invalid modes ignored. */
export function applyDxOverrides(keys: Set<DiagnosisKey>, overrides: Record<string, unknown> | undefined): Set<DiagnosisKey> {
  if (!overrides || typeof overrides !== "object") return keys;
  for (const [k, mode] of Object.entries(overrides)) {
    if (!ALL_DX_KEYS.has(k as DiagnosisKey)) continue;
    if (mode === "suppress") keys.delete(k as DiagnosisKey);
    else if (mode === "add") keys.add(k as DiagnosisKey);
  }
  return keys;
}
```
